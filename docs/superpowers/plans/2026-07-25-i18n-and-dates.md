# Paket 1: i18n und Datumsformatierung — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Abgeschlossen am 2026-07-25 (Commits 9e4c0fb, b348b49, Paritätstest, c886b4f).

**Goal:** Die englische Sprachversion wird real nutzbar und die App zeigt überall dasselbe, sprachabhängige Datumsformat.

**Architecture:** Eine reine Formatierungsfunktion (`ui/src/utils/DateFormat.ts`) kapselt die date-fns-Locale-Wahl und ist ohne React testbar; ein dünner Hook (`ui/src/hooks/useDateFormat.ts`) liefert sie sprachgebunden an die Komponenten. Danach wanderen die hart kodierten deutschen Strings view-für-view in `de.json`/`en.json`, abgesichert durch einen Key-Paritätstest.

**Tech Stack:** React 19, react-i18next 17, i18next 26, date-fns 4, vitest 4 (jsdom, `globals: true`), TypeScript.

## Global Constraints

- Testkommando: `cd ui && pnpm test` (vitest run). Es gibt **kein** `@testing-library/react` — Tests laufen nur gegen reine Module, nicht gegen Komponenten.
- Pfad-Alias: `@` zeigt auf `ui/` (siehe `ui/vitest.config.ts`), Imports also `@/src/...`.
- Übersetzungsdateien: `ui/src/language/json/de.json` und `ui/src/language/json/en.json`. Beide werden **immer gleichzeitig** ergänzt; EN wird echt übersetzt, niemals mit deutschem Text gefüllt.
- Bestehende Key-Gruppen (`dashboard`, `files`, `clubEvents`, `pinboard`, `aiChat`, `offline`, `inventory`, `sections`) bleiben unverändert; neue Strings kommen in neue Gruppen.
- Keine neuen Abhängigkeiten in diesem Paket.
- Commit-Messages auf Englisch, Präfix `feat(ui):` / `refactor(ui):` / `test(ui):` nach Repo-Konvention.

`ui/src/utils/DateFormat.ts`:

```ts
import { format, isValid, parseISO } from "date-fns";
import { de } from "date-fns/locale/de";
import { enUS } from "date-fns/locale/en-US";
import type { Locale } from "date-fns";

// One place decides how dates look. Before this module the app mixed three
// styles — date-fns with a hardcoded German locale, toLocaleString("de-DE")
// and bare toLocaleString() — so the same timestamp rendered differently per
// screen and the English UI showed German dates.
export const resolveDateLocale = (language: string): Locale =>
    language?.toLowerCase().startsWith("de") ? de : enUS;

const formatWith = (iso: string | undefined | null, language: string, pattern: string): string => {
    if (!iso) return "";
    const parsed = parseISO(iso);
    if (!isValid(parsed)) return "";
    return format(parsed, pattern, { locale: resolveDateLocale(language) });
};

/** Date and time, e.g. "04.03.2026, 16:30" / "03/04/2026, 4:30 PM". */
export const formatDateTime = (iso: string | undefined | null, language: string): string =>
    formatWith(iso, language, "Pp");

/** Date only, e.g. "04.03.2026" / "03/04/2026". */
export const formatDateOnly = (iso: string | undefined | null, language: string): string =>
    formatWith(iso, language, "P");
```

- [x] **Step 1: Write the hook**

`ui/src/hooks/useDateFormat.ts`:

```ts
import { useMemo } from "react";
import { useTranslation } from "react-i18next";
import { formatDateOnly, formatDateTime } from "@/src/utils/DateFormat";

// Binds the current i18n language to the pure formatters, so components never
// pass a language (and never reach for a locale) themselves.
export const useDateFormat = () => {
    const { i18n } = useTranslation();
    const language = i18n.language;
    return useMemo(
        () => ({
            formatDateTime: (iso?: string | null) => formatDateTime(iso, language),
            formatDateOnly: (iso?: string | null) => formatDateOnly(iso, language),
        }),
        [language]
    );
};
```

`ui/src/language/i18nParity.test.ts`:

```ts
import { describe, expect, it } from "vitest";
import de from "@/src/language/json/de.json";
import en from "@/src/language/json/en.json";

const flatten = (value: unknown, prefix = ""): string[] => {
    if (typeof value !== "object" || value === null) return [prefix];
    return Object.entries(value).flatMap(([key, child]) =>
        flatten(child, prefix ? `${prefix}.${key}` : key)
    );
};

describe("translation files", () => {
    const deKeys = flatten(de);
    const enKeys = flatten(en);

    it("has no key that exists in only one language", () => {
        const inDeOnly = deKeys.filter((key) => !enKeys.includes(key));
        const inEnOnly = enKeys.filter((key) => !deKeys.includes(key));
        expect({ inDeOnly, inEnOnly }).toEqual({ inDeOnly: [], inEnOnly: [] });
    });

    it("has no empty translation", () => {
        const empty = [...flatten(de), ...flatten(en)];
        expect(empty.filter((key) => key.endsWith("."))).toEqual([]);
    });
});
```
