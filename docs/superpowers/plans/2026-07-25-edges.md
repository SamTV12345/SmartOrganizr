# Paket 4: Kanten — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die verbleibenden rauen Kanten: der AI-Chat wird auf dem Handy benutzbar und folgt dem Theme, die Nachrichtenansicht verhält sich wie ein Chat, Datei-Uploads zeigen Fortschritt und Fehler und lösen dieselbe Live-Aktualisierung aus wie Pinnwand-Beiträge, Pinnwand und Nachrichten laden nicht mehr alles auf einmal, und Register lassen sich umbenennen.

**Architecture:** Serverseitig drei kleine Ergänzungen: seitenweise Chat-Nachrichten (`limit`/`before`), seitenweise Pinnwand (`limit`/`offset`) und eine `club_file`-Benachrichtigung, für die der `ClubFileService` erstmals Hub und Mitgliederliste bekommt. Clientseitig sind es lokale Umbauten in `AIChatPanel`, `MyMessagesView`, `ClubFilesSection`, `ClubPinboardSection` und `ClubDetailView`.

**Tech Stack:** Go 1.26 + Fiber v3 + sqlc, MySQL; React 19 + TanStack Query + vitest.

## Global Constraints

- **Keine Migration.**
- SQL nur in `api_go/data/sql/queries/query.sql`, danach `cd api_go && sqlc generate`.
- Nach Endpunkt-/DTO-Änderungen: `cd api_go && go run github.com/swaggo/swag/cmd/swag@v1.16.6 init --parseDependency --parseInternal -o docs`, dann `cd ui && npx swagger2openapi ../api_go/docs/swagger.json -o ../api_go/docs/openapi.json` und `pnpm dlx --package typescript@5.9.3 --package openapi-typescript@7.13.0 --shell-mode "openapi-typescript ../api_go/docs/openapi.json -o src/api/schema.ts"` (`pnpm gen:api` ist durch den TypeScript-7-Bump kaputt).
- Go-Testumgebung: `container system start`, `socktainer &`, `DOCKER_HOST=unix://$HOME/.socktainer/container.sock`, `TESTCONTAINERS_RYUK_DISABLED=true`.
- Rückwärtskompatibilität: ohne `limit`/`before`/`offset` müssen die Endpunkte sich wie heute verhalten (die bestehenden Tests sind der Wächter).
- Neue Strings in `aiChat.*`, `messages.*`, `files.*`, `pinboard.*`, `sections.*`, immer beide Sprachen.

### Task 1: Seitenweise Chat-Nachrichten (Server)

**Files:**
- Modify: `api_go/data/sql/queries/query.sql`, `api_go/service/messageService.go`, `api_go/controllers/messages.go`
- Test: `api_go/tests/club_messages_test.go` (oder die vorhandene Nachrichten-Testdatei)

**Interfaces:**
- Produces: `(*MessageService).GetChatMessages(clubID, chatID, requesterID string, limit int, before *time.Time) ([]models.ClubChatMessage, error)` — Default-Limit 50, aufsteigend sortiert wie bisher; `before` schneidet strikt älter ab.

Heute lädt jeder Chatwechsel bis zu 500 Nachrichten in einem Rutsch, und es gibt keinen Weg weiter zurück.

- [ ] **Step 1: Write the failing test**

60 Nachrichten in einen Chat seeden (über `testQueries`, damit der Test nicht 60 Requests braucht). Dann: ohne Parameter kommen die neuesten 50 in aufsteigender Reihenfolge; mit `limit=10` genau zehn, und zwar die zehn neuesten; mit `before=<created_at der ältesten geladenen>` die zehn davor, ohne Überlappung.

- [ ] **Step 2: Run and watch it fail**

- [ ] **Step 3: Add two queries**

```sql
-- name: ListClubChatMessagesLatest :many
... WHERE cm.chat_id = ? ORDER BY cm.created_at DESC, cm.id DESC LIMIT ?;

-- name: ListClubChatMessagesBefore :many
... WHERE cm.chat_id = ? AND cm.created_at < ? ORDER BY cm.created_at DESC, cm.id DESC LIMIT ?;
```

Zwei Queries statt einer mit nullable Parameter: sqlc-freundlich und lesbarer. Der `id`-Tiebreaker ist nötig, weil `created_at` nur Sekundenauflösung hat.

- [ ] **Step 4: Service and controller**

Service wählt die Query, dreht das Ergebnis in aufsteigende Reihenfolge (das UI rendert von oben nach unten). Controller liest `?limit=` und `?before=` (RFC3339); ungültige Werte werden ignoriert, nicht abgelehnt.

- [ ] **Step 5: Green, regenerate docs, commit**
